# Reference inputs needed for exact matching

The roleplay implementation uses the saved public references. Those references mix promotional framing, account types, publication dates and devices; they cannot establish complete current applications. Functional tests, shared package hashes and nonblank startup captures do not certify 1:1 appearance.

For each required style, identify the app version/build, country, iPhone model, iOS version, appearance and account/product type. An unaltered recording covering Home → selected transaction → review → result → history supplies the missing transitions and screen geometry. Shopify also needs the selected Products/Menu states. Delivered notification examples establish their title/body, installed identity and sound.

The current pass adds supported bank product/navigation pages; Coinbase Advanced/Rewards/Security; Wealthsimple Chequing/Visa/Crypto/Security; MetaMask mUSD/Money; Phantom Trade; Trust reference states/artwork; Polymarket combos/Squads/Tennis; and Shopify itemized orders. [REFERENCE-COMPLETION.md](REFERENCE-COMPLETION.md) gives concrete review paths and verification status. No additional reference collection is needed to compile, test and review this work.

These remain fictional local interactions. Enrollment, banking authorization, exchange networking, live streaming and actual settlement are not implemented. Coinbase Card/separate Wallet, full banking and brokerage products, unpictured transaction transitions and unseen wallet collectible artwork are not established as matching. Decorative viewports display only the pictured portions of unchanged original JPEGs; Trust's NFT references expose only the top 126 pixels. Saved profiles remain preserved when new-profile seed data changes.

Native verification of the new flows is pending. The earlier native run and comparison gallery validate their pinned application commit, not this working tree. Target-version recordings are needed only to extend the remaining exact-matching claim; physical-device installation, delivered notifications/audio and complete 1:1 appearance remain unverified.

[Visual coverage](VISUAL-COVERAGE.md) identifies the pictured and unpictured states for all 20 styles. [Verification status](STATUS.md) separates executed checks from remaining comparisons. Selecting those target states makes the remaining 1:1 goal concrete and testable.
